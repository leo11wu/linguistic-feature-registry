# LingMetrics：速度与输出体积复测

## 0.2.2：真实大文本与默认精简保存

0.2.0在一份约1 MB、6,788句的文本中展开了23,035,078个句对，产生约869 MB句对CSV，又将相同记录写入约1.31 GB检查点；后续多次读取、反序列化和导出进一步放大耗时。旧运行记录的完整目录含缓存约2.39 GB，用时481.50秒。此前的小篇幅合成文本检查不足以揭示这一问题。

0.2.2用倒排索引计算每对句子的交集、并集大小，只累计整数计数直方图；包括零重叠句对。均值、总体标准差、精确中位数和极值从全部有效句对汇总，双方均为空的句对仍无定义。默认不构造句对字典列表，也不将它写入检查点。显式开启逐对导出时按文档流式写入压缩CSV。段落词数、句数与相邻段落重叠使用有序字符位置查找，口径保留。

默认以gzip无损压缩大于等于1 MB的CSV和冻结参照，更新表清单路径与哈希；拟合和外部参照直接读取。检查点以gzip压缩；仅基础阶段时不另存完整spaCy二进制，无错误完成后清理临时缓存。取消、失败或含`error`的结果保留检查点；用户也可选择始终保留。词、句及模型拟合所需的观测表继续保存，旧版已有输出不自动删除。

真实语料复测的耗时、完整目录体积、峰值内存、配置一致性与逐列核对见[0.2.2复测记录](../metadata/lightweight_validation.json)。对照沿用用户的0.2.0运行记录与同一输入、所选94项指标及参数；属于同一台Mac不同时间的单次运行，不据此承诺固定倍率。原语料与提取数据不随验证记录上传。

## 0.1.1：早期内核优化记录

2026-10-15，macOS 15.7.4 / Apple Silicon，同一台 Mac、同一解释器与基础模型，旧版为 commit `7ba85d58d1119b118705c6a02a01ce36088b4568`。下列结果属于软件性能与数值等价性检查，不代表语言指标的研究效度。

## 改动

- 文档缓存采用紧凑 JSON；所有文档表与明细表合计读取两遍缓存，每次只保留一篇文档。CSV 字段、顺序、缺失规则和原文信息保留。
- 语料参照指标按文档合并写回，复用相同词的离散度及同一文档的 n-gram。只选网络度数时跳过最短路和介数；只选其他网络指标时也只计算相关部分。网络辅助明细因此只包含所选计算产生的列。
- HD-D 复用相同词频的未抽中概率；voc-D 用整数编码合计词型，保留原有三轮抽样、35–50 词样本、每样本的除法、随机种子和拟合方法。
- 依存随机基线分块计算边长，保留每一次 `rng.permutation` 的顺序与次数。分块大小受限，不构造整篇文本的全部随机排列矩阵。
- CMUdict 参考词形、音素映射及双音素计数共用。邻域仍采用完整参考词典、精确编辑距离、20 个最近邻；只排除目标拼写，保留其他拼写的同音词。跨文档词级结果采用至多 32,768 项缓存，拼写长度桶至多 32 个。
- 同一文档的相邻句与间隔句语义指标复用句向量；段落向量独立计算。
- Pythia 的完整上下文仍进入解码器，只为实际计分的位置计算词表投影与归一化。BERT 的每个输入仍只掩码一个 token，完整句子进入注意力层，词表预测头只处理该掩码位置。其他架构保留通用回退路径。
- LM 的词与子词对齐采用有序偏移检索；仍检查跨词歧义与未覆盖词，遇到无序偏移时回退到完整区间匹配。

## 实测与解释

完整数值、每轮耗时、结果哈希和数据规模见 [performance.json](../metadata/performance.json)。

| 场景 | 旧版 | 0.1.1 | 核对范围 |
| --- | ---: | ---: | --- |
| 默认 61 条，100 篇 × 约 1,000 词 | 57.66 s | 25.97 s | 指标矩阵、词次、句子及全部明细 CSV |
| 18 条语料参照／网络指标，25 篇 | 8.147 s | 4.830 s | 16 张 CSV 逐字节一致 |
| 80 节点依存树，5,000 次随机排列 | 47.81 ms | 6.92 ms | 每次排列的总边长及 RNG 后续状态 |
| 多样性指标，20,000 词／4,000 词型 | 20.79 ms | 8.10 ms | 完整数值哈希一致 |
| voc-D，6,000 词 | 24.47 ms | 17.87 ms | D 值一致 |
| 仅 NET01，500 节点／1,500 边 | 192.18 ms | 0.65 ms | 度与强度一致；不再计算未选介数 |
| 四项词典邻域，首篇 128 词 | 1.774 s | 0.806 s | 完整 CMUdict 下的结果哈希一致 |
| BERT 评分内核，随机权重小模型 | 71.79 ms | 4.17 ms | 原始完整词表计算与新路径的分数一致 |

默认及语料批处理各计时一次；数学内核取三轮中位数。文本为重复句式的合成英语，性能随词型数、句长和资源而变，不能据此承诺真实语料的固定倍率。

词典邻域对相同词的后续两篇文本耗时从约 1.46 s 降至约 0.2 ms，属于缓存命中的场景。首次加载与新词仍需实际计算，不能将此倍率推广到词汇完全不同的文本。

BERT 内核使用 30,522 词表、隐藏层 64、2 层、96 token、16 个独立掩码、CPU 2 线程的随机初始化模型；三轮比较使用相同参数。其进程峰值内存从约 661 MiB 降至 316 MiB。该实验核对架构与评分计算，**没有重新测量预训练 BERT、MPNet、Stanza 或 Pythia 的端到端吞吐**。0.1.0 的真实模型试跑记录保留，并标注版本。

新增数值回归核对包含：随机数状态、同音词、自身排除、Unicode/OOV、单掩码 PLL 聚合、Pythia 跨窗口上下文、向量复用边界、歧义对齐与新旧导出。随机初始化 BERT/Pythia 的旧／新分数允许绝对误差 `2e-6`；本次所列 BERT 内核分数逐值相同。

## 使用与复测

正常使用无需改参数。`run.json` 新增 `timings.phases_seconds` 和 `timings.features`，后者记录本次调用的累计秒数与调用次数。加载、共用计算归入首次触发的指标；续算复用部分不计时，不能直接视为指标独立成本。

开发复测入口为 `scripts/benchmark_performance.py`，支持 `batch`、`corpus`、`kernels`、`phonology`、`model`。在两个独立进程中将 `PYTHONPATH` 指向旧／新 `engine`，使用同一基础依赖和输入，并分别指定新输出目录；数学、词典、模型内核默认三轮。词典／模型测试所需可选依赖不进入基础安装包。

0.1.1 的代码和运行签名已更新；原版本的结果不与新版本混合续算。重算请使用新的专属输出目录。

精确近邻查询使用 RapidFuzz 3.14.3 的原生 `process.extract`，编辑距离与截取规则遵循 [官方 API 文档](https://rapidfuzz.github.io/RapidFuzz/Usage/process.html#extract)。原指标定义与资源版本未因性能优化而更换。
